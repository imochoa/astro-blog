## Syntax highlighting

Fenced code blocks are highlighted by Astro's configured highlighter.

```ts title="example.ts"
const greeting: string = "Hello from a highlighted code block";
console.log(greeting);
```

The `title` value is available as fence metadata, but displaying a filename
frame would require a custom code component.

### Local source files with `?raw`

A fence cannot load its contents from another file. Vite's `?raw` import query
loads a local file as a string instead. Pass that string to the blog's
`SourceCode` wrapper to render it with syntax highlighting. The wrapper applies
the site's light and dark Shiki themes to Astro's built-in `Code` component.

```mdx
import SourceCode from "@/ui/SourceCode.astro";
import calloutSource from "@/ui/Callout.astro?raw";

<SourceCode code={calloutSource} lang="astro" />
```

The block below is rendered from the current contents of `Callout.astro`, so the
post does not need a copied version of the component source.

<SourceCode code={calloutSource} lang="astro" />

### Meta-based highlighting

A brace range in the fence metadata highlights selected lines. A `/word/`
pattern highlights matching words.

```ts {2,4-5} /count/
const start = 1;
const count = start + 1;
const label = "not highlighted";
console.log(count);
console.log({ count });
```

### Comment notation

Notation comments are removed from the rendered code after applying their
styles. They can highlight lines or individual words.

```ts
// [!code highlight:2]
const host = "localhost";
const port = 4321;
// [!code word:server:1]
const server = `http://${host}:${port}`;
console.log(server);
```

### Diffs

Use `++` and `--` notation to mark additions and removals.

```ts
const mode = "foreground"; // [!code --]
const mode = "background"; // [!code ++]
```

### Focus and diagnostics

Focused blocks dim the surrounding lines. Error, warning, and info notation can
mark diagnostics without changing the example source.

```ts
const input = "42";
const value = Number.parseInt(input, 10); // [!code focus]
console.log(value);
```

```ts
const count: number = "four"; // [!code error]
const fallback = 0; // [!code warning]
console.log(fallback); // [!code info]
```

These transformers add presentation classes; they do not format source code or
provide folding and copy buttons. Those require a dedicated component.

## Smart punctuation

Straight quotes become “smart quotes”, three dots become an ellipsis..., two
hyphens become an en dash -- and three become an em dash ---.

## Math

Inline math uses single dollar delimiters: $E = mc^2$.

$$
e^{i\pi} + 1 = 0
$$

Sätteri parses the delimiters into math nodes, and the configured KaTeX plugin
renders those nodes as accessible MathML and typeset HTML during the build.

form for a rendered heading.

### Standard HTML elements in MDX

MDX accepts standard HTML elements using JSX syntax. Lowercase names such as
`details` render as HTML; uppercase names refer to imported or locally defined
components. Attributes can contain JavaScript expressions, as shown by the
`progress` and `meter` values below.

<details>
  <summary>Disclosure with details and summary</summary>
  <p>
    The browser supplies the expand and collapse behavior, including keyboard
    support, without a client script.
  </p>
</details>

<figure>
  <pre>
    <code>pnpm run build</code>
  </pre>
  <figcaption>
    A <code>figure</code> groups content with a <code>figcaption</code>.
  </figcaption>
</figure>

<dl>
  <dt>MDX</dt>
  <dd>Markdown with JSX expressions, elements, imports, and exports.</dd>
  <dt>Sätteri</dt>
  <dd>The Markdown processor configured for this site.</dd>
</dl>

A few useful inline elements are <mark>mark for relevant text</mark>,

<abbr title="WebAssembly">Wasm</abbr> for abbreviations,
<time dateTime="2026-08-18">August 18, 2026</time> for machine-readable dates,
and <kbd>Command</kbd> + <kbd>K</kbd> for keyboard input.

<label htmlFor="build-progress">Example build progress</label>
<progress id="build-progress" value={0.65} max={1}>
  65%
</progress>

<label htmlFor="test-score">Example test score</label>
<meter id="test-score" min={0} max={100} low={50} high={80} value={92}>
  92 out of 100
</meter>

Other useful elements include `aside` for tangential content, `address` for
contact information, `ruby` and `rt` for pronunciation annotations, and `dialog`
for a dialog box. A dialog needs a small client script when it should open in
response to a button.

See the [MDX explanation of JSX](https://mdxjs.com/docs/what-is-mdx/#jsx) and
MDN's
[HTML element reference](https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Elements)
for the full list. MDN also documents the behavior and accessibility details of
[`details`](https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Elements/details),
[`figure`](https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Elements/figure),
[`progress`](https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Elements/progress),
and
[`meter`](https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Elements/meter).
